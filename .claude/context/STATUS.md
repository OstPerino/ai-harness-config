## Ключевые решения и почему
- **Источник правды — этот репозиторий, `~/.claude` — симлинки.** Без git правку агента не видно и не откатить.
- **Промпты агентов — английский, отчёты — русский.** Дешевле в токенах на рассуждениях; отчёты читает владелец.
- **Формат агента:** роль 1–2 строки → Workflow → чеклисты (условные по стеку) → Hard rules → Output, 70–150 строк. Без «elite 15+ years» и каталогов технологий: поведение меняют правила.
- **Модели:** `opus` — рассуждения, планы, ревью; `sonnet` — код и тесты. Только алиасы — lint это проверяет.
- **SDD:** одна ветка фичи, партии в worktree, одно ревью, один фикс-раунд тем же исполнителем (SendMessage), итоговое ревью, `pr.md`. Повторного ревью нет (глобальный `CLAUDE.md`).
- **В этом репо коммитится только спека** (`docs/specs/`); `.sdd/` — локально (в `.gitignore`): ревью защиты содержат детали атак, а репо публичный.
- **Атрибуция:** личные проекты — всегда; рабочие (`~/Job`) — по правилам репо, иначе нет.

## Грабли
- **Публичный репозиторий.** Перед push — `git grep -i -E -f "$(git rev-parse --git-common-dir)/info/leak-patterns"` должно быть пусто: рабочие проекты не упоминать. `claude/skills/ui-ux-pro-max/` — сторонний, в `.gitignore`.
- **zsh не разбивает команду из переменной:** `G="git -C x"; $G status` не работает — писать команды явно.
- **Код выхода через пайп теряется** (`cmd | tail` → код `tail`) — `cmd >out 2>&1; rc=$?`.
- **SDD-файлы — не в `.claude/`** (protected path). Worktree — `.worktrees/`, артефакты — `.sdd/`. Этот `STATUS.md` — исключение: на `.claude/context/STATUS.md` завязан хук SessionStart в `~/.claude/settings.json`.
- **`settings.json` не симлинковать:** Claude Code перезаписывает его сам (#007a).
- **Скрипт `run_eval` skill-creator** занижает срабатывания: снимать симлинк проверяемого скилла и запускать с `--num-workers 1` (`tests/evals/README.md`).
- **Локально остался тег `pre-anonymize`** со старой (необезличенной) историей — не пушить; удалить, когда владелец подтвердит, что GitHub в порядке.
