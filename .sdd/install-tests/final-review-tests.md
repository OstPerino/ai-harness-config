## Находки

### [Important] 1. Сценарий dry-run запускается только на пустом `home`, поэтому ветки бэкапа и prune из P2 под `--dry-run` ничем не охранены
- Где: `tests/install.test.sh:106-112`; ветки `install.sh:44-45` и `install.sh:62`
- Сценарий: P1 написал `t_dry_run` на пустом `home`: на месте ссылок нет файлов, висячих ссылок тоже нет. P2 добавил бэкап и prune, но только для обычного прогона. В итоге под `--dry-run` ни один сценарий не доходит до `mv` и `rm`. Проверил мутантами на HEAD:
  - `sed '45s/run mv/mv/' install.sh` → `7/7 passed`, exit 0;
  - `sed '62s/run rm/rm/' install.sh` → `7/7 passed`, exit 0;
  - `sed '44s/run mkdir/mkdir/' install.sh` → `7/7 passed`, exit 0;
  - обе правки вместе (`44s` + `45s`, «`run` убран из бэкапа») → `7/7 passed`, exit 0.

  Что сделает последний мутант на живой машине. У владельца в `~/.claude/agents/` лежит свой агент `a.md` (обычный файл). Владелец запускает `./install.sh --dry-run`, чтобы посмотреть, что изменится. Мутант на самом деле создаёт `backups/harness-<ts>/` и переносит туда `a.md`, а ссылку не ставит: `ln` по-прежнему идёт через `run`. Агент пропадает из `~/.claude/agents`, и всё это на команде «только показать». Гейт при этом зелёный. Мутант `45s` в одиночку данные не переносит (`mv` падает: каталога `$BACKUP` нет), но и его ловить нечем. Обещание спеки «ничего не делает в `--dry-run`» держится только для создания ссылок.
- Исправление: в `t_dry_run` перед `snapshot` подготовить состояние, в котором сработают обе ветки, а `home/skills` не создавать, чтобы осталась под охраной и `install.sh:72`:
  ```sh
  mkdir -p "$sb/home/agents"
  printf 'mine\n' >"$sb/home/agents/a.md"
  ln -s "$sb/repo/claude/agents/gone.md" "$sb/home/agents/gone.md"
  ```
  Ассерты оставить как есть (`assert_status 0`, `assert_tree_unchanged`, `assert_output_contains "[dry-run]"`). Конкретные строки `[dry-run] mv` и `[dry-run] rm` в ассерты не добавлять, иначе `45d` и `62d` уронят и dry-run, и нарушится критерий «только свой сценарий». Проверил на копии раннера во временном каталоге: база `7/7` под sh и dash. Исходная матрица не изменилась: `49d` роняет link и backup, остальные девять (`41d`, `-eq 9`, `24s`, `45d`, `62d`, guard `*)`, guard-префикс, `85d`, `86d`) роняют только свой сценарий. Новые мутанты: `62s run rm→rm`, `44s`, `72s` роняют только dry-run через `assert_tree_unchanged`, `45s run mv→mv` роняет только dry-run через `assert_status` (`mv` в несуществующий `$BACKUP` падает), `44s`+`45s` вместе роняют только dry-run через `assert_tree_unchanged`. В отчёт фикса — эта матрица.

### [Minor] 2. Команда для мутанта в README по-прежнему не запускается при копировании
- Где: `README.md:210`
- Сценарий: строка `sed '<правка>' install.sh > "$m" && …` использует `$m`, но нигде её не задаёт. При копировании `$m` пустая, `> ""` даёт `cannot create`. Это Minor 3 из ревью P1, в фикс не вошёл. Других инструкций по мутантам в фиче нет, это единственная.
- Исправление: начать строку с `m=$(mktemp);`.

### [Minor] 3. Повторный прогон может пересоздавать ссылки, и unchanged этого не заметит
- Где: `tests/install.test.sh:71-78`, `:91-104`
- Сценарий: мутант `sed '41s/return/run ln -sfn "$src" "$dst"; return/'` даёт `7/7 passed` (перепроверено на HEAD). `ls -lAR` не показывает inode, а mtime показывает с точностью до минуты. Это Minor 1 из ревью P1, он не исправлен. После P2 больше ни один сценарий обязательство «не трогает уже поставленное» не проверяет, так что дыра осталась на уровне всей фичи.
- Исправление: `ls -liAR` в `snapshot` (`tests/install.test.sh:72`).

## Стыки

- **Контракт между партиями:** ок. P2 пользуется хелперами P1 по тем же правилам. `assert_file_content` и glob-проверка бэкапа завершаются через `fail` с кодом 70. Значит, цикл раннера отличает упавший ассерт от сломанной подготовки, а новая подготовка из P2 (`rm -r repo/claude/skills/s2`, висячие ссылки) идёт под `set -e` в подоболочке, как предусмотрено fail-closed песочницей P1. Все семь сценариев сверяют итоговую строку `done:` целиком, в одном формате. `rm -r` в `t_prune` бьёт только по `$sb/repo`: `sb` проверен в `sandbox()` (`install-test.??????`).
- **Дублирование:** нет. Песочница одна, обёртка запуска одна. Сценарии P2 готовят состояние руками, как `t_unchanged` из P1, и не запускают для этого скрипт первым прогоном.
- **Стык P1 dry-run ↔ P2 backup/prune:** дыра, см. Important 1. Каждая партия закрыла своё. Пересечение («бэкап и prune под `--dry-run`») не попало ни в один бриф. P2 отметил это в «Не сделано», ревью P2 это не подняло.
- **Порядок миграций:** не применимо.
- **Гейт:** `CLAUDE.md` (ключ `Гейт:`) и критерий спеки — одна и та же строка `sh tests/lint-harness.sh && bash -n install.sh && sh tests/install.test.sh`. В README те же три команды стоят отдельными строками блока, без `&&`.
