**Предмет:** коммиты `sdd/install-tests..sdd/install-tests-P1` (`6a2cc91`, `006affd`) на `sdd/install-tests-P1`, бриф `.claude/context/sdd/install-tests/P1-brief.md`, отчёт `.claude/context/sdd/install-tests/P1-report.md`.

Проверено командами: гейт `sh tests/lint-harness.sh && bash -n install.sh && sh tests/install.test.sh` зелёный, `4/4 passed`; под `dash` и `bash` тоже `4/4`, exit 0; `find ~/.claude/agents ~/.claude/skills ~/.claude/CLAUDE.md -maxdepth 1 -newer <marker>` после трёх прогонов пусто; `git status --short` в worktree пуст; после штатных прогонов и прогонов с FAIL в `$TMPDIR` не остаётся `install-test.*`.

## Находки

### [Critical] Если `mktemp` не сработал, песочницей становится текущий каталог, и на выходе его удаляет `rm -rf`
- Где: `tests/install.test.sh:17-19`, `:115`
- Сценарий: `TMPDIR` указывает на несуществующий или закрытый на запись каталог (вычищенный `/var/folders/.../T`, переопределённый `TMPDIR` в сэндбоксе агента, переполненный диск). `mktemp` падает, `sb=""`. `set -e` не срабатывает: подоболочка стоит в условии `if ( sandbox; "$fn" )`, а там `-e` игнорируется (проверено в sh/bash 3.2, dash и bash). Дальше `sb=$(cd "" && pwd)`: `cd ""` во всех трёх шеллах возвращает 0 и остаётся на месте, так что `sb` = `$PWD`. `${sb:?}` не помогает, переменная не пустая. Раннер создаёт `repo/`, `home/`, `out` и снимки прямо в текущем каталоге, запускает в нём install.sh, а EXIT-трап выполняет `rm -rf "$PWD"`. Гейт запускают из корня репо, так что пропадает всё рабочее дерево вместе с `.git`. Проверил на копии раннера, где `rm -rf` заменён на `echo`, cwd — scratch-каталог, команда `TMPDIR=/nonexistent sh|dash <копия>`. На каждом сценарии: `mktemp: mkdtemp failed …`, затем `WOULD_RM_RF /tmp/rev-probe.…/cwd`; в cwd остались `home out repo snapshot.after snapshot.before`. Ровно эту утечку в дерево репозитория бриф назвал главным риском.
- Исправление: в `sandbox` проверять каждый шаг явно, потому что `set -e` здесь не действует: `sb=$(mktemp -d "${TMPDIR:-/tmp}/install-test.XXXXXX") || exit 1`, `[ -n "$sb" ] && [ -d "$sb" ] || exit 1`, `sb=$(cd "$sb" && pwd) || exit 1`, затем страховка `case "${sb##*/}" in install-test.??????) ;; *) exit 1 ;; esac`. `trap` ставить только после этих проверок. В отчёт фикса — прогон `TMPDIR=/nonexistent sh tests/install.test.sh` из пустого временного cwd: ненулевой exit, cwd не тронут, ни одного `ok`.

### [Important] Раннер печатает `ok`, хотя подготовка сценария сломалась: `set -eu` из шапки внутри сценариев выключен
- Где: `tests/install.test.sh:2`, `:115`
- Сценарий: подоболочка в условии `if` выполняется без `-e`. Поэтому исход сценария определяет только последняя команда, а упавшие `mkdir`, `cp`, `ln -s`, `mktemp` и `snapshot` раннер пропускает. В том же прогоне с `TMPDIR=/nonexistent` вышли `ok link`, `ok unchanged` (с тремя `ln: … File exists` в stderr) и `ok dry-run`: песочницы не было, а тесты зелёные. В P2 подготовки станет больше (`mv`, `rm -r repo/claude/skills/s2`, висячая чужая ссылка), и её сбой будет зеленеть, если только последний ассерт случайно его не заметит.
- Исправление: вынести подоболочку из условия и включить `-e` в ней: `set +e; ( set -e; sandbox; "$fn" ); rc=$?; set -e; if [ "$rc" -eq 0 ]; then …`. Под sh, dash и bash проверено: так `-e` внутри подоболочки работает (`rc=1` после `false`). Critical этим не закрывается, потому что `cd "" && pwd` завершается успешно. Нужны обе правки.

### [Minor] `assert_tree_unchanged` не замечает пересоздание ссылки
- Где: `tests/install.test.sh:60-62`
- Сценарий: `ls -lAR` показывает mtime с точностью до минуты, inode не показывает. Мутант `sed '41s/return/run ln -sfn "$src" "$dst"; return/'` пересоздаёт все пять ссылок на каждом прогоне, а счётчик оставляет `unchanged=5`. Результат: `4/4 passed`. Отчёт пишет, что снимок «показывает mtime», но это верно только с точностью до минуты. Обещание «второй прогон не трогает `home`» в этом месте не соблюдается.
- Исправление: `ls -liAR` (POSIX, inode пересозданной ссылки меняется), либо отметить в отчёте, что unchanged проверяет итоговое состояние, а не отсутствие записей.

### [Minor] Под dash песочница остаётся в `$TMPDIR` после SIGTERM
- Где: `tests/install.test.sh:19`
- Сценарий: `kill -TERM` группе процессов во время сценария. Под dash EXIT-трап не срабатывает, и `install-test.XXXXXX` с `home out repo` остаётся в `$TMPDIR`. Воспроизведено, остаток я удалил. Под `/bin/sh` (bash 3.2) каталог убирается. Настоящий `~/.claude` при этом не задет, страдает только временный каталог.
- Исправление: в `sandbox` рядом с EXIT поставить `trap 'exit 129' HUP; trap 'exit 130' INT; trap 'exit 143' TERM`, тогда отработает EXIT-трап.

### [Minor] В README команда для мутанта не задаёт `$m`
- Где: `README.md` (раздел «Проверка харнесса», строка «Чтобы проверить тест мутантом»)
- Сценарий: если скопировать строку как есть, `$m` пустая, и выходит `> ""` с ошибкой `cannot create`. Вреда нет, но пример не запускается.
- Исправление: начать строку с `m=$(mktemp);`, как в ручной проверке отчёта.

## Мутации из отчёта

Все четыре воспроизведены на коммите `006affd`. Перед каждой проверял `diff install.sh "$m"`, правка ровно одна. Прогон под sh и dash.

| мутант | результат |
|---|---|
| `49d` | `FAIL link: symlink …/home/agents/a.md / not a symlink`, остальные `ok`, `3/4 passed`, exit 1 |
| `41d` | `FAIL unchanged: output contains 'linked=0 unchanged=5 …' / … linked=5 unchanged=5 backed_up=5 …`, остальные `ok`, `3/4` |
| `-eq 1` → `-eq 9` | `FAIL dry-run: …/home unchanged / <diff с пятью ссылками>`, остальные `ok`, `3/4` |
| `24s/exit 1/exit 0/` | `FAIL bad-arg: exit status 1 / exit status 0`, остальные `ok`, `3/4` |

Каждый мутант роняет свой сценарий нужным ассертом и не задевает остальные. Решение готовить `unchanged` руками, а не первым прогоном, обосновано: link фиксирует точную абсолютную форму цели, unchanged проверяет, что в этой форме ничего не меняется. Вместе они покрывают «второй прогон ничего не делает» без двойного FAIL на `49d`. Мои дополнительные мутанты: `ln -sfn` в ветке unchanged выживает (см. Minor выше); лишний хвост в строке `done:` выживает, это ожидаемо, `grep -F` ищет подстроку.
