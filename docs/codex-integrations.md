## Учёт времени

Перед обработкой относительных дат получить `whoami`: использовать `tz`,
`today` и `yesterday`, возвращённые сервисом. Не подставлять автоматически
часовой пояс компьютера. Проект выбирать через `find_projects` или проверенный
Jira key; не придумывать идентификатор по названию.

Перед записью прочитать `list_entries` за нужные даты, чтобы не создать дубликат.
Само подключение или проверка MCP не разрешает записывать часы. При поручении
записать время использовать фактические даты, минуты и проект; для повторов
сохранять одинаковые idempotency keys. `log_time` допускает `dryRun`, а правка
существующей записи использует `version` из чтения. Не запускать и не
останавливать таймер ради проверки подключения.

## Браузер

Выбран один backend: Playwright MCP 0.0.84, Apache-2.0. Проверен ранее
установленный пакет с закреплёнными зависимостями; его `node_modules` скопированы
из локального npm cache в отдельный каталог
`~/.codex/harness/runtimes/playwright-0.0.84`. Подключение не зависит от дальнейшей
очистки npm cache. Пакетный менеджер при подключении не запускался.

Пользовательский config содержит абсолютные пути к уже установленному Node.js
и `@playwright/mcp/cli.js`, аргументы `--browser chrome --isolated --headless`.
При удалении выбранной версии Node.js путь потребуется обновить. На другой
машине наличие Node.js, пакета и Chrome проверяется отдельно: installer харнесса
не устанавливает эти зависимости и не переносит локальные MCP credentials.

Схему инструментов читать через `tools/list`: в проверенной версии клик принимает
`target`, снимок — `scale`, network — `static`. Ответ на навигацию может содержать
ссылку на файл snapshot, а не сам текст страницы. Для действий достаточно
обычных browser tools; запуск произвольного Node.js-кода не нужен.

Источник: [Playwright MCP](https://github.com/microsoft/playwright-mcp).
Профиль `--isolated` не использует cookies личного браузера.

## Дизайн

`frontend-design` и `ui-ux-pro-max` включены только в адаптер Codex. Их исходники,
лицензии и SHA upstream находятся в `adapters/codex/skills/`; renderer включает
их в release, штатный installer устанавливает ссылки. Общие Claude-файлы
при этом не меняются. Предыдущую самостоятельную копию UI UX Pro Max перед
первым переходом под управление installer сохранить в пользовательский backup;
не удалять её и не ослаблять проверку коллизий установщика.

Frontend Design задаёт визуальное направление, UI UX Pro Max ищет в локальных
каталогах. Принятый бриф, бренд проекта и выбранный режим соло/SDD сохраняются.
Поиск не пишет файлы; `--persist` применяется только при поручении сохранить
design system, с явным `--output-dir`. Сохранённые решения не заменяются без
соответствующей задачи.

## Состояние клиента

После добавления MCP или skills обновить каталог инструментов/перезапустить
клиент, если текущий диалог их ещё не видит. Прямой MCP smoke подтверждает
сервер; наличие инструментов в конкретном диалоге проверяется отдельно.

Guard оставлен выключенным по явному решению владельца. Проверенные локальные
guard-тесты не означают, что отключённый hook защищает текущий диалог.

Context7 подключён к официальному [MCP endpoint](https://github.com/upstash/context7)
через HTTP. В запросы документации не включать секреты или закрытый код проекта.
