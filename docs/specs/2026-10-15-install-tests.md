# Тесты для install.sh — спека

**Issue:** нет · **Дата:** 2026-10-15 · **Статус:** утверждена

## Зачем

`install.sh` перемещает и удаляет файлы в `~/.claude`, а проверен только вручную. Тесты фиксируют его пять обязательств (ставит ссылки, не трогает уже поставленное, бэкапит чужие файлы, убирает свои висячие ссылки, ничего не делает в `--dry-run`) и два ограничения (не трогает чужие ссылки, отклоняет неизвестный аргумент). Ломается любое из них — гейт харнесса краснеет.

## Граница

**Делаем:** раннер `tests/install.test.sh` на POSIX `sh` без зависимостей, 7 сценариев, мутационное доказательство каждого, строка в гейте и README.

**Не делаем:** CI; правки `install.sh` (баг, найденный тестами, — находка в отчёте); `-h/--help`.

## Решения

### ADR-1: песочница копирует скрипт, а не ставит из настоящего репо
- Контекст: сценарию prune нужно удалить исходный файл; удалять из живого `claude/` нельзя.
- Решение: каждый тест — подоболочка `( … )` со своим `trap 'rm -rf "$sb"' EXIT` (в POSIX sh trap глобальный, внутри функции при падении он не сработает); в песочнице `repo/install.sh` — копия, `repo/claude/` — фейковое дерево `agents/a.md`, `agents/b.md`, `skills/s1/SKILL.md`, `skills/s2/SKILL.md`, `CLAUDE.md`, `home/` — `CLAUDE_HOME`. `rm -rf` защищён от пустой переменной.
- Отвергнуто: bats-core — зависимость на каждой машине.
- Последствия: + тесты не трогают ни `~/.claude`, ни репозиторий; − фейковое дерево надо держать в синхроне с тем, что ставит скрипт (`agents/*.md`, `skills/*/`, `CLAUDE.md`).

### ADR-2: мутанты подставляются через `INSTALL_SH`
- Контекст: доказательство теста — мутация скрипта, а раннер сам копирует настоящий `install.sh`.
- Решение: путь к копируемому скрипту берётся из `INSTALL_SH`, по умолчанию `<корень>/install.sh`. Мутант: `sed '<правка>' install.sh > /tmp/m.sh && INSTALL_SH=/tmp/m.sh sh tests/install.test.sh`.
- Отвергнуто: путь аргументом раннера — смешивается с будущими аргументами (фильтр сценариев).
- Последствия: одна строка в раннере, `install.sh` не меняется.

## Приёмка

- [ ] `sh tests/install.test.sh` → `7/7 passed`, exit 0 — команда.
- [ ] Тот же раннер под `dash tests/install.test.sh` → `7/7 passed` — команда.
- [ ] Каждая из 7 мутаций роняет свой сценарий, и только его — таблица мутаций в отчётах партий. Исключение: мутант `49d` (`link`) роняет и `backup` — backup обязан проверять ссылку на месте файла (решение ведущего 2026-10-18).
- [ ] Во время прогона ни один файл в настоящем `~/.claude` не изменился — `find ~/.claude/agents ~/.claude/skills -maxdepth 1 -newer <метка>` пусто.
- [ ] Гейт харнесса `sh tests/lint-harness.sh && bash -n install.sh && sh tests/install.test.sh` указан в README.

## Безопасность

security-reviewer: нет — ни auth, ни доступов, ни секретов, `install.sh` не меняется. Риск — порча данных при прогоне (скрипт двигает и удаляет файлы); его закрывают ADR-1 и критерий приёмки про `~/.claude`, проверяет ревьюер партий.

## Открытые вопросы

- `assert_tree_unchanged` на `ls -l` включает mtime и права; внутри одного прогона стабильно. Ложные срабатывания → перейти на `find -exec stat`. Не блокирует.
- Найдено попутно, вне границы: `BACKUP` с точностью до секунды (`install.sh:7`) — два прогона в одну секунду пишут в один каталог бэкапа и могут перезаписать одноимённые файлы. Кандидат в задачу #007.
