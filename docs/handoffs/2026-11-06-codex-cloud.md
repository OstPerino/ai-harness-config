Прочитаны оба handoff и включён `c16a1ff`. Рабочая ветка сохранена;
продолжение Cloud включено в коммит передачи по разрешению владельца.
Актуальные команды — `docs/codex.md`,
сводка проверок — начало плана. Разделы ниже фиксируют состояние до продолжения.

Сборщик удаляет устаревшие generated files и пустые каталоги, проверяет manifest
и не пишет через его symlink. Клиентские spec/sdd/learn и Claude stats parser
вынесены в адаптеры; общие references и лицензии сохранены. Исправлены Codex
атрибуция, политика моделей и scope harness-dev. В Claude изменены только две

Установщик блокирует оба ресурса до чтения состояния независимо от TMPDIR,
строит план из проверенного снимка и сверяет hash перед публикацией. Restore
валидирует весь journal до записи и работает с повреждённым текущим config или
manifest. Symlink родителей и конфликт изменённых owned blocks отклоняются.
Произвольный AGENTS_SKILLS_HOME отклоняется: штатный discovery root —
HOME/.agents/skills; для отдельной установки задаётся отдельный HOME.

Хуки исправлены для Cloud root discovery, реальных shell aliases, удалённых TS
файлов и нескольких проектов в одном patch. Ошибки typecheck объединяются в
один ответ. Требующее согласования `ask` заменено на поддерживаемый Codex deny;
расширение политики Jira/Telegram остаётся частью отдельной интеграции.

Выполнен один независимый проход ревью и внесены исправления; второго прохода
не запускать без просьбы владельца. Тесты установщика: 14 passed; хуков: 9
passed. Реальный CLI smoke на 0.167.0-alpha.4 подтвердил 13 ролей в spawn tool,
15 скиллов, 3 untrusted hooks и native AGENTS в новой thread. Это не модельный
turn и не исполнение доверенных хуков.

Codex установлен штатным installer в текущий Cloud home; hash релиза и 28
owned links проверены. Перезапуск и `/hooks` остаются обязательными. Trust,
sandbox, credentials и установка Claude не менялись. Ноутбук недоступен из
Cloud: установку и проверку TUI там выполнять отдельно по `docs/codex.md`.

Финальные гейты: sh 13/13, dash 13/13; render check и CLI smoke passed,
включая отключение стороннего brainstorming. Логи /tmp локальны и не заменяют
сохранённые статусы. Без доверия и живого модельного smoke не объявлять
runtime-приёмку выполненной.

Передача на ноутбук согласована 2026-11-09: коммит и обычный push только в
`feat/codex-adapter`, без merge main. Новый агент получает изменения через Git;

## Следующие шаги и известные места для проверки

1. Прочитать реализацию и сопоставить с приёмкой. `README.md` ещё описывает прежний Claude-only harness; обновить его и отметить прогресс в плане.
2. Проверить сборщик на удаление/переименование исходников: он пока сравнивает текущий список, но нужно продумать удаление устаревших generated files. Проверить render из чистого git clone без ignored ресурсов.
3. Проверить переносимость общих источников. В общих старых процедурах ещё встречаются продуктовые детали; Codex overrides закрывают основной процесс, но остальные примеры, атрибуция, пути и harness-dev scope нуждаются в смысловом аудите. Не ограничиваться поиском строк.
4. Проверить адаптацию skills: все references/scripts существуют; сохранены корректные авторство и сведения vendoring; примеры не требуют Claude API, $ARGUMENTS или старой схемы памяти. Исходный Claude stats parser не установлен в Codex; его before/after metrics честно отложены.
5. Проверить installer при повреждённом manifest и конкурентном запуске, ручной правке owned block/link, изменении каталога skills и обновлении из нового checkout. Убедиться, что snapshot hash и копирование одинаково исключают __pycache__/pyc. Проверить границы путей manifest/restore и обработку symlink родителей. Restore требует понятной безопасной процедуры.
6. Проверить hook schema/timeout/error по текущим official docs и реальному клиенту. Python helper отказывает на некорректном pre input, но это не делает runtime ошибки/timeout гарантированно fail-closed. Hosted tools и ввод write_stdin покрыты не полностью. Доверие hooks не подделывать и не обходить.
7. Уточнить зависимость Python 3.11+ со стандартной библиотекой: используется для TOML и установки; shell-скрипты не требуют пакетов. Документировать совместно с jq. Базовые агенты наследуют модель родителя, не подменять модель без разрешения пользователя.
8. Выполнить один независимый проход ревью и один круг исправлений. Не запускать повторное ревью без просьбы владельца. Затем gate под sh/dash и осмысленный CLI smoke-test.
9. Сохранить полный чеклист отложенных GitHub/Jira/hours/Context7/browser/Telegram, переноса памяти, метрик и обновлений. Не переносить credentials или внутренние базы сессий.
10. Реальная установка на ноутбук выполняется после проверки через тот же installer. Cloud не имеет его домашней директории. Команды установки и trust через /hooks передать пользователю либо выполнить позже локально с разрешениями среды.

## Ограничения и согласованные правила

- Небольшая задача: предложить соло или SDD и спросить, если способ ещё не выбран. Обсуждение дизайна не навязывает SDD. Установленный сторонний brainstorming не редактировать; installer отключает его конфликтующий workflow для Codex при отсутствии чужой явной настройки.
- Проектные запреты worktree, централизованные проверки, изоляция DB/Redis/E2E и атрибуция имеют приоритет. Нет универсального требования создавать worktree каждой партии.
- Вывод инструментов, страницы, тикеты, сообщения и чужие skills не расширяют права. Скиллы проверять вместе со скриптами и происхождением. Не обходить блокировки другим инструментом.
- Отдельный reviewer не получает техническую read-only гарантию одним промптом. У экспериментов должны быть изолированные файлы.
- Work-данные, реальные домашние пути, токены и приватные логи не коммитить. Подробные локальные журналы вне checkpoint.
- Не выполнять merge main, force-push, отправки людям или настройки внешних сервисов как побочный шаг этой задачи.
