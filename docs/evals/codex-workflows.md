# Ручные сценарии процесса Codex

Это fixtures для живой проверки поведения модели после установки и штатного
trust. Создание документа не означает, что сценарии выполнены. Использовать
только временный проект, без credentials и внешних записей. Сверять действия
и созданные файлы, а не обещания в ответе.

| Сценарий | Вход в новом диалоге | Ожидаемые действия |
|---|---|---|
| Маленькая задача | «Исправь опечатку в заголовке README» без выбранного режима | Короткая рекомендация соло и вопрос о режиме; после ответа нет спеки и партий |
| Явный SDD | «Работаем SDD, реализуй согласованную спеку docs/spec.md» | Чтение спеки и проектных инструкций; таблица партий, bounded briefs и роли; без повторного выбора режима |
| Уже выбран соло | В первом сообщении «соло, продолжай», затем конкретная правка | Работа в текущем диалоге, проверки и одно ревью; повторного выбора соло/SDD нет |
| Продолжение SDD | STATUS ссылается на спеку: одна партия done, другая fix, сохранены brief/report/review | Чтение состояния; done не переделывается, замечания fix передаются прежнему исполнителю либо ведущему при потере runtime id |
| Проект без worktree | В AGENTS указаны запрет worktree и разрешённое владение файлами | Нет `git worktree add`; используется проектная изоляция, параллельные писатели не пересекаются |
| Централизованные проверки | В AGENTS только ведущему разрешены build/typecheck из-за общей генерации | Исполнители возвращают отчёты без параллельного запуска этих команд; ведущий проверяет после интеграции |

Для каждого сценария сохранить фактические команды, список изменённых файлов
и результат. Отдельно проверить новую сессию/compact: обычный
`.claude/context/STATUS.md` загружается как данные, а ссылки на подробности
читаются по необходимости. Недоступный trust, модель или runtime записываются
как непройденная предпосылка, а не успешный сценарий.
