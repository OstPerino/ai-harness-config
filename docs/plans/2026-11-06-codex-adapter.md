## 4. События Codex и защитные проверки

Файлы: `codex/hooks/`, общие защитные функции при извлечении, `codex/config/`, `tests/codex-hooks.test.sh`. Существующие тесты guard/typecheck не ослаблять.

- [ ] Сверить реальные схемы событий, patch и отказов текущего клиента. Нельзя считать Claude payload правильным только из-за совпадения имени события.
- [ ] Описать преобразование каждого используемого события в вход guard-проверок. Для patch учесть все пути добавления, изменения, удаления и перемещения.
- [ ] Проверить границы пути после нормализации, относительные пути и симлинки. Синтетические сценарии не должны читать настоящие секреты или писать вне temp.
- [ ] В защитном событии повреждённый payload, отсутствие зависимости и ошибка проверки дают понятный отказ, а не успех. Поведение timeout проверить отдельно.
- [ ] Сохранить проверки опасных сетевых команд, удаления, изменения защищённых настроек и операций Jira. Не обещать полное покрытие чтения секретов только shell-хуком.
- [ ] Подключить SessionStart к общему статусу; проверить обычный файл, отсутствие файла и отказ от symlink.
- [ ] Подключить typecheck после patch; проверить TS, Vue и Rust через фальшивые tools в temp, полный вывод ошибки и отсутствие повторных запусков одного проекта в одном событии.
- [ ] Объединить новые hooks с чужими без удаления и дубликатов.
- [ ] Проверить trust штатным интерфейсом. Не подделывать trust-файлы и не включать bypass доверия по умолчанию.
- [ ] В инструкции назвать пределы покрытия: hosted tools, интерактивный ввод, отдельные opt-out пути. Разрешения файловой системы и сети проверяются отдельно.
- [ ] Детальные результаты атакующих проверок хранить локально; в публичном отчёте — проверяемые гарантии и ограничения без частных данных.

## 5. Установщик и восстановление

Файлы: `install.sh`, `scripts/install-codex.sh`, при необходимости небольшой helper для форматов, `tests/codex-install.test.sh`, дополнения `tests/install.test.sh`.

- [ ] Прежний `./install.sh` по умолчанию устанавливает Claude как раньше. Добавить явные цели `--target codex|claude|all` и понятный help.
- [ ] Предусмотреть `CODEX_HOME` и `AGENTS_SKILLS_HOME`; тесты задают только временные каталоги. `CLAUDE_HOME` продолжает работать.
- [ ] До первой записи проверить весь план и форматы. Битый TOML/JSON/manifest, неизвестная цель и отсутствующий исходник не должны оставлять частичную установку.
- [ ] Сохранять пользовательские AGENTS/config/hooks и чужие агенты/скиллы. Одинаковое имя чужого файла — явный конфликт, а не повод перезаписать его.
- [ ] Manifest фиксирует только принадлежащие харнессу элементы и прежние значения. При обновлении пользовательская последующая правка сохраняется.
- [ ] Backups не перезаписываются при двух установках за одну секунду. Есть проверенный путь восстановления прежних файлов и ссылок.
- [ ] Полный набор Codex копируется в `CODEX_HOME/harness/releases/<content-id>`, ID определяется содержимым. Установленные ссылки смотрят в этот неизменяемый release, а не в worktree. После копирования проверить состав и hashes до переключения ссылок.
- [ ] Проверить rollback на предыдущий release и восстановление owned-настроек; не удалять прежний release, пока на него ссылается установка или backup.
- [ ] Реализовать отказ/восстановление после искусственного сбоя между записями config, hooks и manifest.
- [ ] Проверить чистую, повторную, пробную установки; обновление/удаление owned элементов; чужие равные элементы; сломанную ссылку; частично завершённую предыдущую операцию.
- [ ] Проверить отдельно: target codex не меняет Claude; target claude не меняет Codex; all корректно обрабатывает обе цели.
- [ ] Реальная установка Codex из worktree разрешена благодаря полному release snapshot. Проверить в тесте, что после удаления копии исходного дерева установленные файлы доступны. Для Claude сохраняется прежняя защита ветки и install-from-worktree.

## Дальнейшие пункты до полного переноса

Эти задачи согласованы как отдельное направление. Не подключать сервисы и не публиковать внешние записи только ради отметки в чеклисте.

### Интеграции

- [ ] GitHub: выбрать доступный plugin/MCP или `gh`, проверить чтение issue/PR, создание черновика PR, согласованную запись и правила атрибуции.
- [ ] Jira: перенести подключение без credentials в git, проверить чтение, согласование записи, запрет удаления и проектные исключения.
- [ ] Учёт часов: перенести подключение и точные правила проектов/дат; пробную запись выполнять только при явном разрешении владельца.
- [ ] Context7: проверить доступ и механизм авторизации, получить документацию реально используемой библиотеки.
- [ ] Playwright/браузер: проверить запуск локального приложения, screenshot, console/network, E2E и изолированный стенд.
- [ ] Telegram: оставить приостановленным до отдельного решения. При возобновлении проверить индекс чатов, отдельного исполнителя, режим чтения и разрешение отправки точного текста.
- [ ] Credentials выдавать минимально необходимым сервисам; не копировать токены из Claude config в репозиторий или общие шаблоны.

### Память и проекты

- [ ] Проверить проекты с вложенными инструкциями, запретом worktree, общей сборкой, изолированными БД/Redis/E2E и запретом публичной атрибуции.

## Когда задача завершена

Codex установлен и подтверждён настоящей сессией; общие тексты собираются проверяемо; Claude не потерял прежние пути и настройки; тесты проходят; оставшиеся интеграции и ручные проверки перечислены с честными статусами. Отсутствующая авторизация внешнего сервиса не объявляется выполненным подключением.
