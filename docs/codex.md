# Codex: установка и обновление

Требуются POSIX shell, bash для `install.sh`, jq и Python 3.11+ со стандартной
библиотекой. Пакеты Python не нужны. Проверенный клиент и результаты текущего
прогона записаны в плане адаптации; поддержка другой версии требует её проверки.

## Установить

Из checkout нужной ветки:

```sh
sh scripts/render.sh --check
./install.sh --target codex --dry-run
./install.sh --target codex
```

При установке через агента используются эти же команды. `--target claude`
и прежний вызов без цели устанавливают Claude. `--target all` устанавливает
обе цели и принимает только `--dry-run`; операции restore/uninstall/release
выполняются отдельно для Codex. Установка двух клиентов не является общей
транзакцией: сбой второй цели не отменяет первую.

По умолчанию используются `~/.codex` и `~/.agents/skills`. `CODEX_HOME` можно
переопределить. `AGENTS_SKILLS_HOME` принимается только равным штатному
`HOME/.agents/skills`: произвольный каталог клиент не обнаруживает. Для отдельной
установки задайте отдельный HOME вместе с обоими путями. Проверки используют
временные каталоги. Уже установленный каталог skills нельзя менять простым
переопределением переменной: сначала удалить старую установку с прежними путями.

Installer копирует `codex/` в `CODEX_HOME/harness/releases/<content-id>`.
Ссылки ролей и скиллов ведут в этот релиз, поэтому удаление исходного checkout
их не ломает. `AGENTS.md` и `config.toml` дополняются отмеченными блоками,
`hooks.json` объединяется с чужими определениями. Manifest хранит принадлежность
записей и путь исходного checkout. Ручные изменения принадлежащего установщику
блока или ссылки вызывают конфликт; чужие настройки сохраняются.

После установки перезапустите Codex и просмотрите определения в `/hooks`.
Доверие подтверждается штатным интерфейсом. Installer не записывает trust,
не меняет sandbox, разрешения сети, модель или авторизацию. Облачная установка
не переносится в домашний каталог ноутбука автоматически.

## Обновить правила

Менять `shared/` и `adapters/`, затем:

```sh
sh scripts/render.sh
sh tests/gate.sh
SH=dash dash tests/gate.sh
python3 tests/codex_cli_smoke.py
./install.sh --target codex
```

`render --check` ничего не записывает. После удаления исходника обычная сборка
удаляет прежний generated file по `.generated-files`; остальные файлы сохраняет.
Установленные релизы не редактировать. Для новой установки используется новый
content-id. Старые релизы сохраняются для возврата и backups.

```sh
./install.sh --target codex --release <content-id>
./install.sh --target codex --uninstall
./install.sh --target codex --restore <полный-путь-из-строки-backup>
```

Restore возвращает затронутые установкой файлы и ссылки в состояние backup,
включая их отсутствие до установки. Более поздние изменения этих файлов будут
заменены: перед restore сохраните их отдельно. Сначала используйте `--dry-run`.
Restore не требует исправного текущего TOML или manifest, но проверяет весь
journal и наличие копий до записи. Не редактируйте backup/journal вручную.
При обычном исключении installer сам откатывает изменения. После аварийного
завершения с оставшимся `harness/install.lock` убедитесь, что процесс завершён,
сохраните текущие файлы, удалите пустой lock-каталог и выполните restore из
backup этой операции. Не удаляйте блокировку работающего установщика.

## Что переносится

| Возможность | Состояние |
|---|---|
| 13 ролей | TOML; модель и reasoning наследуются, имя модели не подменяется |
| spec, sdd, learn | Отдельные процедуры Codex; учитывают уже выбранный режим и одно ревью |
| project-checkpoint | Общий обычный `.claude/context/STATUS.md`, без симлинков |
| domain-modeling, git-flow, humanize, project-architect | Общие тексты и references; проект и резюме задаёт пользователь |
| systematic-debugging, test-driven-development, verification-before-completion | Общие vendored материалы с MIT и сведениями об источнике |
| issue-start, issue-done | Процедуры доступны; подключение трекера проверяется отдельно |
| harness-stats | Проверка состояния установки; метрики транскриптов Codex отложены |
| Telegram | Установлен для явного вызова, интеграция приостановлена |

`learn`, `harness-stats` и Telegram не вызываются неявно. При обнаружении
стороннего `brainstorming` installer отключает его автоматический workflow
настройкой Codex, сохраняя исходники. Явная чужая настройка `enabled = true`
вызывает конфликт. Проектные AGENTS и инструкции владельца имеют приоритет;
worktree и централизованные проверки выбираются по проекту.

Подключения hours, Jira, Context7, Playwright и дизайн-скиллы описаны в
[codex-integrations.md](codex-integrations.md).

## Хуки и проверка клиента

`SessionStart` загружает STATUS как данные проекта. `PreToolUse` преобразует
shell/patch в вход общих guard-проверок; patch проверяется по всем путям,
включая удаления и перемещения. `PostToolUse` запускает typecheck для каждого
затронутого TS/Vue/Rust проекта один раз. Общие shell guard/typecheck остаются
совместимыми с Claude; преобразование событий находится в адаптере Codex.

До доверия хукам их наличие не означает действующую защиту. Hosted tools,
обёртки исполнения и ввод в уже запущенный shell через `write_stdin` покрыты
не полностью. Timeout, авария интерпретатора и некоторые ошибки runtime
отмечаются клиентом как ошибка хука и не гарантируют отказ инструмента.
Helper возвращает явный deny при распознанной ошибке pre-input или зависимости;
это не заменяет ограничения файловой системы и сети.

Упоминание каталога установленного харнесса в Python-диагностике само по себе
не означает запись. Для inline `python3 -c` и heredoc проверяется ограниченный
AST-профиль: чтение файлов/метаданных и read-only запросы `hooks/list` и
`skills/list` к штатному app-server. Операции записи, неизвестные импорты,
непрозрачные скрипты и изменяющие RPC не получают исключение. Это консервативная
проверка известных форм диагностики, а не полноценная Python sandbox;
неподдерживаемая форма кода может быть отклонена даже без побочных действий.

Для простых команд `cat` и `rg` имена файлов и поисковые строки не считаются
командами записи. Исключение не разрешает перенаправление вывода, подстановку
команд или параметры `rg`, запускающие внешнюю программу. Ложный отказ одного
действия не останавливает независимую разрешённую работу. По поручению владельца
guard исправляется в исходниках и обновляется штатным installer; активный
технический запрет не обходится другим инструментом.

Установщик сохраняет самостоятельные TOML-таблицы, которые Codex дописал после
собственных настроек внутри управляемого блока, и выносит их за маркеры.
Собственные настройки должны оставаться неизменными. Значения доверия и
включения хуков сохраняются, поэтому временно отключённый guard после обновления
нужно включить через `/hooks` и подтвердить изменившиеся определения.

Codex PreToolUse не поддерживает `permissionDecision: ask`: такой ответ
не блокирует операцию. Поэтому адаптер отклоняет требующие согласования записи
Jira и сообщения Telegram через поддерживаемый `deny`. Чтение доступно;
существующее явно настроенное исключение Jira autocreate остаётся отдельным
правилом проекта. Для других записей сначала нужна проверенная интеграция с
нативным подтверждением клиента; одно согласие в диалоге не изменяет hook policy.

После доверия проверить в новом диалоге: роли видны, STATUS загружен,
безопасная правка проходит, синтетическая правка защищённого файла блокируется,
ошибка typecheck показывается полностью. Использовать временные файлы и home.
Не проверять защиту на настоящих credentials и не включать bypass trust ради
smoke-test. Statusline и недельные лимиты проверяются в TUI авторизованного
клиента; TOML и app-server discovery не доказывают их отображение.
