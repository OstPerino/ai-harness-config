# Проверка срабатывания скиллов

Наборы фраз «должен сработать / не должен» для `spec` и `sdd`, по 20 в каждом. Прогоняются через `run_eval.py` из плагина skill-creator: каждая фраза уходит в `claude -p`, результат — сработал ли проверяемый скилл.

## Как запускать

```bash
R=~/Projects/ai-harness-config
SC=$(ls -d ~/.claude/plugins/cache/claude-plugins-official/skill-creator/*/skills/skill-creator | tail -1)
s=spec   # или sdd

rm ~/.claude/skills/$s
(cd "$R" && mkdir -p .claude && PYTHONPATH="$SC" python3 -m scripts.run_eval \
  --eval-set "$R/tests/evals/$s-triggers.json" --skill-path "$R/claude/skills/$s" \
  --model claude-opus-5-5 --runs-per-query 3 --timeout 60 --num-workers 1)
"$R/install.sh"
```

## Почему именно так

- **Симлинк проверяемого скилла снимается на время прогона.** `run_eval` кладёт копию скилла под временным именем `<скилл>-skill-<id>` в `.claude/commands/` и засчитывает срабатывание, только если вызвана эта копия. Установленный настоящий скилл перехватывает фразы, и срабатывание засчитывается как промах. Второй скилл (`sdd` при проверке `spec` и наоборот) остаётся установленным — он конкурирует за похожие фразы, как в жизни.
- **`--num-workers 1`.** Параллельные воркеры кладут свои копии в одну папку, каждый запуск видит все копии и вызывает любую. Засчитывается только своя — срабатывания занижаются.
- **`mkdir -p .claude` в корне репозитория.** `run_eval` ищет корень проекта по папке `.claude/`. Без неё он поднимется до `~` и будет класть копии в `~/.claude/commands/`.
- **superpowers отключён.** Иначе его brainstorming перехватывает фразы вроде «давай сделаем фичу».

Порог — 18 из 20 по каждому скиллу, и обязательные «не должен» не срабатывают. Цена прогона — 60 вызовов `claude -p` на скилл.
