# PROJECT.md template

Это структура, которую заполняет skill при генерации проектного документа. Заголовки разделов — на английском (для читаемости в IDE / GitHub). Содержимое — билингва: технические термины на английском, описания и обоснования можно на русском.

Используй markdown. Не плоди раздутых разделов — для pet-project каждый раздел должен умещаться в несколько абзацев или короткий список.

## Принципы заполнения

1. **Не лей воду.** Каждое предложение должно нести смысл. Pet-project документ не должен читаться как production RFC.
2. **Будь конкретным в технологиях.** Не "какая-нибудь БД", а "Postgres" / "SQLite" / "DuckDB" — с обоснованием.
3. **Билингва осознанно.** Названия фич, разделов, технологий — на английском. Обоснования и описания — на русском (живо, не суконно).
4. **Если чего-то не хватает — оставь TODO.** Лучше явный `<!-- TODO: уточнить нужен ли auth -->`, чем додуманное решение.
5. **Помни про scope.** Pet-project / weekend-build. Если документ начинает выглядеть как enterprise SaaS — режь.
