# #007 — Репозиторий харнесса: git, установщик, задел под другие LLM

**Статус:** 007a/b/c сделаны 2026-10-19 (PR #2), остался 007d — другие LLM
**Создано:** 2026-10-12

## Проблема
`~/.claude` не под git: агенты, скиллы, `settings.json`, `CLAUDE.md` живут просто в папке, откатиться некуда. В dotfiles лежит только `statusline.sh`.

## Решение (черновик)
- `~/Projects/ai-harness-config` — источник правды под git.
- Установщик раскладывает агентов, скиллы, хуки и настройки в `~/.claude` (симлинки или копирование — решить).
- Структура такая, чтобы потом собирать конфиг под другие инструменты (Codex `AGENTS.md`, Gemini и т.д.). Образец — superpowers, у которого есть `AGENTS.md`, `GEMINI.md`, `gemini-extension.json`.
- Тесты харнесса: валидность frontmatter агентов и скиллов, матчеры хуков — это регулярки по имени инструмента, блокировка через `exit 2`, контекст отдаётся через stdout JSON. Именно эти ошибки нашлись в ECC.

## Критерии готовности
- [ ] Чистая установка на новую машину одной командой.
- [ ] Тесты харнесса зелёные в CI.

## Разбивка на будущее (решено 2026-10-18)
- **007a — settings и хуки под управлением репозитория.** `settings.json` не симлинкуется: Claude Code сам его перезаписывает. `install.sh` вливает наш кусок (`claude/settings.json`) в `~/.claude/settings.json` через `jq`, хуки — файлы в репозитории, покрыты тестами.
- **007b — хуки качества.** typecheck и форматирование после правки, полный вывод. Закрывает #003.
- **007c — CI харнесса.** GitHub Actions: `tests/lint-harness.sh`, `tests/install.test.sh`, тесты хуков.
- **007d — другие LLM.** После #005, когда формат агентов устоится.
- Мелочи: `install.sh` не запускает lint перед раскладкой; каталог бэкапа с точностью до секунды (`install.sh:7`) — два прогона в одну секунду могут перезаписать одноимённые файлы.
