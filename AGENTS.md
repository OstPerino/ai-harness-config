# ai-harness-config

Общие правила, роли и скиллы — в `shared/`. Данные клиентов — в `adapters/claude/` и `adapters/codex/`. `claude/` и `codex/` содержат готовые файлы; их создаёт `sh scripts/render.sh`. Не редактируй собранный файл вместо его исходника. Текущий статус сессии — `.claude/context/STATUS.md`, если он есть.

Владелец выбирает соло в текущем диалоге или SDD после краткой рекомендации агента. Если выбор уже сделан в разговоре, повторно не спрашивать. Обсуждение дизайна не обязывает запускать SDD. Одно независимое ревью, исправления и проверки; второй круг ревью только по явной просьбе.

Основной checkout остаётся на `main`: установленный Claude читает файлы через симлинки. Работай в `.worktrees/`, используй `git -C` для других деревьев. Сохраняй чужие незакоммиченные изменения. Не меняй настоящий `~/.claude` при установке Codex.

Shell — POSIX sh, старый `install.sh` использует bash. Для разбора TOML и транзакционной установки Codex используются Python 3.11+ и стандартная библиотека; сторонние Python-пакеты не нужны. Ничего не устанавливай пакетным менеджером. Не добавляй пояснительные комментарии в код.

Проверки: `sh scripts/render.sh --check`, `sh tests/gate.sh`, `SH=dash dash tests/gate.sh`. Тесты меняют только временные копии и каталоги, задают `CLAUDE_HOME`, `CODEX_HOME`, `AGENTS_SKILLS_HOME` и не трогают настоящий home. Exit-коды проверок не брать через pipe.

Коммиты: `type(scope): subject`, scope из `.gitflow`, заголовок до 72 символов. Эмодзи добавляет commit-msg hook. Атрибуция — фактически использованный инструмент; не приписывай Codex-работу Claude. Не публикуй частные имена, домашние пути и содержимое секретов.

Для ревью: конкретный сценарий поломки, файл и место, предложение исправления. Отсутствие Edit/Write в роли не является отдельной sandbox. Мутационные эксперименты — во временной копии. Сообщения людям и публикация изменений — только в пределах текущего разрешения владельца.
